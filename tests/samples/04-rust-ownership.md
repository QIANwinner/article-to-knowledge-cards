# Rust 所有权三讲

> 测试用虚构讲义。内容为围绕 Rust 所有权机制编写的教学示例，代码片段与报错信息用于检验
> `make-knowledge-cards` 对代码块与编译错误的处理能力，不代表官方文档表述。

## 讲一：所有权规则

Rust 的所有权规则只有三条：每个值有且只有一个所有者；同一时刻只能有一个所有者；所有者离开
作用域，值被丢弃。

一段代码：

```rust
let s1 = String::from("hello");
let s2 = s1;
println!("{}", s1);
```

这段代码编译不过。`let s2 = s1;` 把所有权从 `s1` 移动（move）到了 `s2`，此后 `s1` 不再有效。
编译器报 `error[E0382]: borrow of moved value: s1`。

## 讲二：栈与堆的分工

`String` 由三部分组成：栈上的指针、栈上的长度、堆上的字符数据。前两个在栈上，第三个在堆上。
赋值（move）只拷贝栈上的指针和长度，堆数据不动——所以 move 是廉价的，不涉及深拷贝。

这解释了一个细节：如果 move 触发深拷贝，`let s2 = s1` 在数据量大时会有可观测的性能开销；实测
中这个开销为零，因为堆指针被直接搬走了。

## 讲三：Copy 与克隆的区别

不是所有类型都会 move。整数、浮点数、布尔、字符，以及完全由这些类型组成的元组，都实现了
`Copy` trait。对 `Copy` 类型做赋值是复制而不是移动，原变量仍然可用：

```rust
let x = 5;
let y = x;
println!("{}", x);  // 合法
```

而 `String`、`Vec<T>`、`Box<T>` 没有实现 `Copy`，因为它们在堆上有数据，复制会导致双重释放。

## 讲四：借用与引用

移动太激进，多数时候我们只想读一个值，不想拿走所有权。引用 `&T` 提供只读借用：

```rust
fn length(s: &String) -> usize {
    s.len()
}
```

`&T` 在栈上是一个指针，指向原值。所有权不发生转移，函数结束后指针销毁，原值还在。

可变引用 `&mut T` 是互斥的：同一时刻只能有一个 `&mut` 指向同一个值，也不能同时存在 `&` 和
`&mut`。这条规则在编译期就排除了数据竞争，因此 Rust 不需要运行时检查。

Rust 的借用规则被称为 NLL（非词法生命周期）：借用在最后一次使用后就结束，而不是必须持续到
作用域末尾。这让上面那个函数即使在调用后继续使用原变量也能通过编译。
