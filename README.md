# make-knowledge-cards

把一篇文章或一个本地 Markdown / TXT 文件，转成**最多 128 张知识卡片**。每张卡片只讲一个知识点，附带标题、核心知识、简明解释，以及一个例子或一道自测题。

这是一个 Agent Skill，只输出一份 Markdown 文本，没有界面、没有依赖、不联网。

---

## 1. 这个项目解决什么问题

读一篇文章最费时间的不是读，是读完就忘。收藏夹里躺了五十篇文章，真正记住的不到两成。手动做笔记又慢：复制、粘贴、改写、分类，一篇文章要十分钟。

把文章丢给大模型让它「总结成要点」，问题更常见——输出看起来整齐，但里面混着原文没说过的话。**模型天然倾向于把内容补全成一篇完整的文章**，而读者要的是「原文实际说了什么」。数量也不可靠：明明原文只有两个有效观点，它照样给你凑满五条。

这个 Skill 解决的就是这件事：

| 常见问题 | 本 Skill 的处理 |
|---|---|
| 要点真假混杂 | 每条都要能指回原文的具体行，指不回去就不写 |
| 内容重复啰嗦 | 同一主张的不同表述合并成一张卡 |
| 内容注水 | 原文只有一个观点就只出一张卡，不凑数 |
| 悄悄补全 | 禁止引入原文外的定义、数字、案例 |
| 术语读不懂 | 只能用原文自身用法解释，解释不了就标注「原文未定义」 |
| 摘要脱离原文后误当事实 | 原文的虚构声明、数据时效声明强制带到输出里 |
| 原文自相矛盾时被抹平 | 保留冲突并标注，不替原文做和稀泥 |

核心判断标准只有一条：**能否被原文反驳**。能被反驳的才算知识点，待办、计划、预测、未决问题都还不是断言，因此不做卡。

## 2. 主要功能

### 一张卡一个知识点

每张卡片固定包含四个字段，另有一个按需出现的字段：

| 字段 | 是否必填 | 内容 |
|---|---|---|
| 标题 | 必填 | 具体的知识点本身（`冷启动为什么杀死协同过滤`），不是话题领域（`推荐系统`） |
| `核心知识 / Core knowledge` | 必填 | 一到三句，就是主张本身，带原文的数字、条件、名称 |
| `简明解释 / Plain explanation` | 必填 | 拆解机制或解释术语，**不引入新事实** |
| `口径提示 / Caveat` | 按需 | 仅在原文自相矛盾、统计口径不一致、或原文自带免责声明时出现 |
| `例子 / Example` 或 `自测题 / Self-test` | 必填（二选一） | 不可同时出现 |

字段标签在任何语言下都保持双语，卡片正文语言跟随原文（中文原文出中文卡，英文原文出英文卡）。

### 去重

同一主张在不同段落重复出现，只保留一处。判定标准：两个候选若「换个说法在说同一件事」，或「其中一个没有另一个的句子就讲不通」，则合并。

反过来说，两个候选若**共用一句原文但各自携带对方没有的载荷**（不同的数字、不同的结论、不同的机制环节），则保留为两张卡。

### 不编造

这是硬约束，不是偏好：

- 不补充教科书定义、真实统计数字、原文未提的名字
- 例子只能来自原文，或是基于原文数字的显式算式，且算式必须展示（`1850 − 1540 = 310`）
- 不把主张安到原文没引用的研究者、机构或论文头上
- 不把「日期截至上周」换算成具体日期，除非原文给了日期

### 不凑数，也不拆分

卡片数量由原文内容决定，**128 张是上限，不是指标**：

| 强候选数量 | 产出 |
|---|---|
| ≤ 128 | 一候选一卡，全部保留，无需省略 |
| > 128 | 超出部分延后或省略，footer 说明 |
| 0 | 不出卡，提示原文只有计划或未决问题 |

原文偏薄时（只有两三个观点），就只出两三张卡，footer注明偏薄。

**上限提高后新增一条约束：不为凑数拆分。** 128 张的空间足够，绝不能把一个完整知识点切成两张卡片来填数。这是这次扩容最需要防的退化。

**待办、计划、未决问题、预测都不做卡** —— 这些还没有断言，无法被反驳。原文里有这类内容时，会记进 footer 的「未收录」，不会被静默丢掉。

### 长文自动分批

一次输出上百张卡片没人读得下去，所以超过一定数量会按主题分批：

| 卡片总数 | 交付方式 |
|---|---|
| 1 到 25 | 单批输出，不分批 |
| 26 到 60 | 单批输出，但按原文小节分组 |
| 61 到 128 | **按主题分批**，每批一个标题，卡片编号跨批连续 |

超过 128 张时，在原文自己的小节边界切分；小节内部放不下时，在话题边界切。分批只是传输方式，不是拆成多副牌组 —— 编号从「卡片 1」连续到「卡片 128」，footer 只在最后一批出现一次。

即使你要求「一次给全」，超过约 60 张仍会分批，并说明原因。

### 保留原文声明

如果原文写了「本文为虚构样本」「数据截至 2025 年」「仅供参考」，这类声明会出现在 footer 的「来源声明」行，且带数字的卡片会在 `口径提示` 里重复一次。脱离原文后，读者仍能看出这些数字不是真实统计。

### 保留原文矛盾

原文口径不一致、自相矛盾或给出两个互斥解释时，卡片会保留冲突并标注，不会替原文做判断。

### 术语处理

原文没定义的术语，只用原文自身的用法解释。解释不了时在解释末尾标注：

```
原文未定义「可寻址堆」，本卡只用它在原文中的具体表现。
```

不会为了让读者「看懂」而补一个教科书定义——那等于引入原文外的信息。

### 代码与命令

技术类内容里的代码片段、命令、日志、编译报错，按优先级落位：

1. 默认放进 `例子 / Example`，原文照抄
2. 仅当 Example 已被代码块占用时，编译报错、终端输出才放进 `核心知识`（内联形式）

## 3. 不支持

| 不支持 | 说明 |
|---|---|
| 网页抓取 | 不联网、不解析 URL，请直接粘贴正文 |
| PDF / Word / Excel / PPT | 仅支持粘贴的文本与本地 `.md` / `.txt` |
| 导出 Anki | 不生成 `.apkg` 或导入用CSV |
| 图形界面 | 只输出 Markdown 文本 |

遇到这几类输入时，Skill 会说明哪部分不被支持，并请你粘贴正文或指向 Markdown / TXT 文件，不会自己找变通办法。

## 4. 安装方法

本 Skill 无依赖、无需构建、无需环境变量。复制目录即可。

### 个人级安装（所有项目可用）

```bash
git clone <你的仓库地址>
cp -r make-knowledge-cards/skills/make-knowledge-cards ~/.workbuddy/skills/
```

Windows PowerShell：

```powershell
git clone <你的仓库地址>
Copy-Item -Recurse make-knowledge-cards\skills\make-knowledge-cards "$env:USERPROFILE\.workbuddy\skills\"
```

### 项目级安装（随仓库分发，团队共享）

```bash
cp -r make-knowledge-cards/skills/make-knowledge-cards <你的项目>/.workbuddy/skills/
```

### 验证安装

```bash
python <skill-creator路径>/scripts/quick_validate.py ~/.workbuddy/skills/make-knowledge-cards
```

输出 `Skill is valid!` 即安装成功。校验脚本随 WorkBuddy 内置的 `skill-creator` 提供，路径通常在应用资源目录下。

## 5. 使用方法

安装后无需特殊语法，直接说明需求即可。

**粘贴正文**

```
把下面这篇文章做成知识卡片：

<粘贴正文>
```

**指定本地文件**

```
用 make-knowledge-cards 处理 ./docs/notes.md
```

**指定语言与偏好**

```
readings/2024-cache.md 这篇，帮我拆成卡片，自测题用中文
```

**触发词**：知识卡片、知识卡、读书卡片、卡片化、做成卡片、make cards、knowledge cards、flashcards。

Skill 会自动读取文件、判断原文是否够格、筛选候选、去重、按原文顺序输出，并在 footer 说明卡片数、来源与未收录内容。

## 6. 输入输出示例

### 输入

一个信息量很小的值班速记 `notes.txt`：

```text
快速记录，三件事。

1. 服务器今天重启了两次，都是内存打满自动触发的 OOM Killer。
2. 值班的时候记得确认监控告警通道是否正常，上周那次是告警短信发不出去，我们才知道磁盘满了。
3. 下周把日志清理脚本加上自动删除 30 天前的文件。

另外客户又问了一次那个接口超时的事，我先记在这里，还没定方案。
```

### 输出

原文只有两条可被反驳的断言，因此只出 2 张卡，第 3 条待办和末尾的未决问题不制卡：

```markdown
### 卡片 1 / Card 1. 服务器当天两次重启均由 OOM Killer 触发

**核心知识 / Core knowledge**
服务器"今天"重启了两次，两次都是内存打满后自动触发的 OOM Killer。

**简明解释 / Plain explanation**
原文未定义 OOM Killer，只说明它在"内存打满"时会被自动触发；本卡只用它在原文中的具体表现。原文给出的因果链只有一条：内存被打满 → OOM Killer 自动触发 → 服务器重启，两次重启共用这条链条。原文未给出具体数值——既没有记录内存占用量，也没有说明是什么负载把内存打满。

**自测题 / Self-test**
问：原文记录的这台服务器当天重启了几次？触发原因是什么？
答案：两次，都是内存打满后自动触发的 OOM Killer。

### 卡片 2 / Card 2. 上周磁盘写满未被及时发现，直接原因是告警短信发不出去

**核心知识 / Core knowledge**
上周磁盘已经写满，但值班人员没有通过告警得知——原因是告警短信发不出去，问题是在事后才暴露的。原文据此要求值班时确认监控告警通道是否正常。

**简明解释 / Plain explanation**
这里出问题的是把告警送到人手里的那条通路，而不是磁盘监控本身：磁盘写满这个信号已经产生，通道却断了，信号没有送达，于是发现时间被推到了故障发生之后。原文给出的对应动作是值班时先确认监控告警通道是否正常。原文未定义"监控告警通道"包含哪些通道，只提到告警短信这一种。

**自测题 / Self-test**
问：上周磁盘写满为什么没有被及时发现？
答案：告警短信发不出去，监控告警通道未确认正常，问题是在事后才暴露的。

---
**卡片数 / Cards**: 2
**来源 / Source**: notes.txt
**未收录 / Omitted**: 原文偏薄，卡片数由内容决定而非凑数——第 3 条"下周把日志清理脚本加上自动删除 30 天前的文件"是计划，末段接口超时"还没定方案"是未决问题，二者都没有可被反驳的断言，故未做成卡片。
```

注意几个细节：

- **没有凑到 5 张**。原文只有两个断言，就只出两张卡
- **待办没有变成卡片**。「下周加自动删除」没有断言，不满足「可被反驳」
- **术语没有越界**。OOM Killer 的机制原文没说，就标注「原文未定义」，而不是补一段教科书解释
- **没有「来源声明」行**。原文没有免责声明，这一行会被整行省略，而不是填「无」
- **footer 说明了为什么只有 2 张**。省略理由和数量决策一起交代

| 部分 | 作用 |

## 9. 设计约束

构成这个 Skill 底线的硬规则：

- **可追溯**：任何数字、日期、名称、因果主张，都要能指回原文的具体行
- **不引入外部知识**：不补充教科书定义、真实统计数字、原文未提的名字
- **例子只能来自原文**，或基于原文数字的显式算式，且算式必须展示
- **不虚构权威**：不把主张安到原文没引用的人或机构头上
- **不改分类凑数**：把待办包装成卡片不增加假事实，但会虚增数量，禁止
- **不为凑数拆分**：一个知识点就是一张卡。上限提高后尤其要防把完整知识点切成多张
- **术语不越界**：原文没定义的术语只能用原文自身用法解释，解释不了就标注
- **保留声明与矛盾**：虚构声明、口径冲突、原文互斥说法都要留在输出里
- **保留来源自己的时间表述**（「上周」「今天」），除非原文给了具体日期

## 10. 测试覆盖

`tests/samples/` 下4 类样本分别验证了：

| 样本 | 类型 | 验证点 |
|---|---|---|
| `01-tech-cache.md` | 英文技术文 | 四级 tie-break、省略说明 |
| `02-news-foldable-cn.md` | 中文长分析文 | 重复论述去重、口径不一致标注、虚构声明在卡片与footer 的双重保留 |
| `03-thin-notes.txt` | 极简短笔记 | 只出 2 张卡且不凑数、待办与未决事项不制卡、footer 措辞 |
| `04-rust-ownership.md` | 技术讲义 | 代码块与编译器报错的落位顺序、术语兜底边界、跨小节取材 |

> ⚠️ **所有样本均为虚构测试数据**，标题、数字、厂商与结论均不对应任何真实企业、产品或市场判断，仅用于检验 Skill 行为。每个样本文件头部都写明了这一点。

Skill 说明书经过三轮迭代：每轮用子代理按`SKILL.md` 实际跑全部样本，收集「哪里需要执行者自己猜」的报告，据此修补说明书规则。第一轮补入资格判定表、Caveat 字段、术语规则、派生数字规则、声明保留规则；第二轮补入 tie-break 裁决、artifact 落位顺序、footer 可选字段；第三轮补入枚举拆分规则、声明落位、术语判定阈值。
