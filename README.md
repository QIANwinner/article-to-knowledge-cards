# make-knowledge-cards

[![CI](https://github.com/QIANwinner/article-to-knowledge-cards/actions/workflows/ci.yml/badge.svg)](https://github.com/QIANwinner/article-to-knowledge-cards/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/QIANwinner/article-to-knowledge-cards?display_name=tag)](https://github.com/QIANwinner/article-to-knowledge-cards/releases/latest)
[![License](https://img.shields.io/github/license/QIANwinner/article-to-knowledge-cards?color=4b6bff)](LICENSE)

把一篇文章或一个本地 Markdown / TXT 文件，转成**最多 128 张知识卡片**。每张卡片只讲一个知识点，附带标题、核心知识、简明解释，以及一个例子或一道自测题。

这是一个 Agent Skill，只输出一份 Markdown 文本，没有界面、没有依赖、不联网。仓库同时附带一个本地 GUI 与 2.5 MB 的 Windows 可执行文件。

**v0.1.5 起，GUI 补上了「生成之后」那一段**：卡片会存进本地卡片库，可以逐张编辑、打标签、导出到 Anki / Obsidian / JSON，并按间隔重复（SM-2 变体）安排复习。原文与卡片都只留在本机。

**English README**: [README.en.md](README.en.md) · **在线 Demo**: [qianwinner.github.io/article-to-knowledge-cards](https://qianwinner.github.io/article-to-knowledge-cards/)（浏览器直接用，无需下载）

## 1. 这个项目解决什么问题

读一篇文章最费时间的不是读，是读完就忘。收藏夹里躺了五十篇文章，真正记住的不到两成。手动做笔记又慢：复制、粘贴、改写、分类，一篇文章要十分钟。

把文章丢给大模型让它「总结成要点」，问题更常见——输出看起来整齐，但里面混着原文没说过的话。**模型天然倾向于把内容补全成一篇完整的文章**，而读者要的是「原文实际说了什么」。数量也不可靠：明明原文只有两个有效观点，它照样给你凑满五条。

这个 Skill 解决的就是这件事：

| 常见问题 | 本 Skill 的处理 |
|---|---|
| 要点真假混杂 | 每条都要能指回原文的具体行，指不回去就不写 |
| 内容重复啰嗦 | 同一主张的不同表述合并成一张卡 |
| 内容注水 | 原文只有一个观点就只出一张卡，不凑数 |
| 悄悄补全 | 禁止引入原文外的定义、数字、案例 |
| 术语读不懂 | 只能用原文自身用法解释，解释不了就标注「原文未定义」 |
| 摘要脱离原文后误当事实 | 原文的虚构声明、数据时效声明强制带到输出里 |
| 原文自相矛盾时被抹平 | 保留冲突并标注，不替原文做和稀泥 |

核心判断标准只有一条：**能否被原文反驳**。能被反驳的才算知识点，待办、计划、预测、未决问题都还不是断言，因此不做卡。

## 2. 主要功能

### 卡片库与复习闭环

生成不是终点。这批卡片接下来去哪，是这个版本补的部分：

| 能力 | 说明 |
|---|---|
| 本地卡片库 | 一键把一批卡片存入本机（`localStorage`），按来源归档；关掉浏览器/exe 都不丢 |
| 卡片编辑 | 逐字段改写标题、核心知识、解释、口径提示、例子；改完「原文未提供」标记自动解除 |
| 标签与筛选 | 打标签，按状态、来源、关键词、「只看待补解释」筛选 |
| 间隔重复 | SM-2 变体 + 三档自评（想不起来 / 很费力 / 想起来了），到期时导航徽标亮起 |
| 四种导出 | Markdown / Anki CSV / JSON（含调度状态，可原样导回）/ Obsidian 双链笔记 |
| 备份导入 | 库导出为单个 JSON 文件，换机器或换浏览器时导入回来 |
| 质量报告 | 展开可看到每个候选为什么被拒、哪些解释是原文没写的、哪些重复被合并 |

> **为什么是 SM-2 而不是 FSRS**：FSRS 用 17 个权重拟合遗忘曲线，效果更好，但权重需要按个人数据标定。没有标定数据时套FSRS，只会得到一个「看起来高级但不可信」的间隔。等卡片过百、有真实的「记得/忘了」记录，再换不迟。

### 一张卡一个知识点

每张卡片固定包含四个字段，另有一个按需出现的字段：

| 字段 | 是否必填 | 内容 |
|---|---|---|
| 标题 | 必填 | 具体的知识点本身（`冷启动为什么杀死协同过滤`），不是话题领域（`推荐系统`） |
| `核心知识 / Core knowledge` | 必填 | 一到三句，就是主张本身，带原文的数字、条件、名称 |
| `简明解释 / Plain explanation` | 必填 | 拆解机制或解释术语，**不引入新事实** |
| `口径提示 / Caveat` | 按需 | 仅在原文自相矛盾、统计口径不一致、或原文自带免责声明时出现 |
| `例子 / Example` 或 `自测题 / Self-test` | 必填（二选一） | 不可同时出现 |

字段标签在任何语言下都保持双语，卡片正文语言跟随原文（中文原文出中文卡，英文原文出英文卡）。

### 去重

同一主张在不同段落重复出现，只保留一处。判定标准：两个候选若「换个说法在说同一件事」，或「其中一个没有另一个的句子就讲不通」，则合并。

反过来说，两个候选若**共用一句原文但各自携带对方没有的载荷**（不同的数字、不同的结论、不同的机制环节），则保留为两张卡。

### 不编造

这是硬约束，不是偏好：

- 不补充教科书定义、真实统计数字、原文未提的名字
- 例子只能来自原文，或是基于原文数字的显式算式，且算式必须展示（`1850 − 1540 = 310`）
- 不把主张安到原文没引用的研究者、机构或论文头上
- 不把「日期截至上周」换算成具体日期，除非原文给了日期

### 不凑数，也不拆分

卡片数量由原文内容决定，**128 张是上限，不是指标**：

| 强候选数量 | 产出 |
|---|---|
| ≤ 128 | 一候选一卡，全部保留，无需省略 |
| > 128 | 超出部分延后或省略，footer 说明 |
| 0 | 不出卡，提示原文只有计划或未决问题 |

原文偏薄时（只有两三个观点），就只出两三张卡，footer注明偏薄。

**上限提高后新增一条约束：不为凑数拆分。** 128 张的空间足够，绝不能把一个完整知识点切成两张卡片来填数。这是这次扩容最需要防的退化。

**待办、计划、未决问题、预测都不做卡** —— 这些还没有断言，无法被反驳。原文里有这类内容时，会记进 footer 的「未收录」，不会被静默丢掉。

### 长文自动分批

一次输出上百张卡片没人读得下去，所以超过一定数量会按主题分批：

| 卡片总数 | 交付方式 |
|---|---|
| 1 到 25 | 单批输出，不分批 |
| 26 到 60 | 单批输出，但按原文小节分组 |
| 61 到 128 | **按主题分批**，每批一个标题，卡片编号跨批连续 |

超过 128 张时，在原文自己的小节边界切分；小节内部放不下时，在话题边界切。分批只是传输方式，不是拆成多副牌组 —— 编号从「卡片 1」连续到「卡片 128」，footer 只在最后一批出现一次。

即使你要求「一次给全」，超过约 60 张仍会分批，并说明原因。

### 保留原文声明

如果原文写了「本文为虚构样本」「数据截至 2025 年」「仅供参考」，这类声明会出现在 footer 的「来源声明」行，且带数字的卡片会在 `口径提示` 里重复一次。脱离原文后，读者仍能看出这些数字不是真实统计。

### 保留原文矛盾

原文口径不一致、自相矛盾或给出两个互斥解释时，卡片会保留冲突并标注，不会替原文做判断。

### 术语处理

原文没定义的术语，只用原文自身的用法解释。解释不了时在解释末尾标注：

```
原文未定义「可寻址堆」，本卡只用它在原文中的具体表现。
```

不会为了让读者「看懂」而补一个教科书定义——那等于引入原文外的信息。

### 代码与命令

技术类内容里的代码片段、命令、日志、编译报错，按优先级落位：

1. 默认放进 `例子 / Example`，原文照抄
2. 仅当 Example 已被代码块占用时，编译报错、终端输出才放进 `核心知识`（内联形式）

## 3. 不支持

| 不支持 | 说明 |
|---|---|
| 网页抓取 | 不联网、不解析 URL，请直接粘贴正文 |
| PDF / Word / Excel / PPT | 仅支持粘贴的文本与本地 `.md` / `.txt` |
| 模型补写解释 | 引擎只搬运原文里有的推导；引不到就标「原文未提供」，需要模型补全时用「复制提示词」 |
| 网页剪藏 | 同「网页抓取」，不联网 |

导出 Anki 由 **GUI 负责**（卡片库 → 导出 Anki，生成 tab 分隔 CSV，带 BOM，Excel 与 Anki 都不乱码），**Skill 本身不写 `.apkg` 或导入文件**。这条分工写进了 `SKILL.md` 的 Out of scope，避免两边说法不一致。

遇到网页链接或办公文档时，Skill 会说明哪部分不被支持，并请你粘贴正文或指向 Markdown / TXT 文件，不会自己找变通办法。

## 4. 安装方法

本 Skill 无依赖、无需构建、无需环境变量。复制目录即可。

### 个人级安装（所有项目可用）

```bash
git clone https://github.com/QIANwinner/article-to-knowledge-cards.git
cp -r article-to-knowledge-cards/skills/make-knowledge-cards ~/.workbuddy/skills/
```

Windows PowerShell：

```powershell
git clone https://github.com/QIANwinner/article-to-knowledge-cards.git
Copy-Item -Recurse article-to-knowledge-cards\skills\make-knowledge-cards "$env:USERPROFILE\.workbuddy\skills\"
```

### 项目级安装（随仓库分发，团队共享）

```bash
cp -r article-to-knowledge-cards/skills/make-knowledge-cards <你的项目>/.workbuddy/skills/
```

### 验证安装

```bash
node scripts/check-skill.js
```

输出 `结果：全部通过` 即安装成功。该脚本校验 frontmatter、命名规范、工作流完整性与关键约束章节。

### 前端界面（可选）

前端界面**无需安装**，只要有 Node.js（≥ 18）即可：

```bash
git clone https://github.com/QIANwinner/article-to-knowledge-cards.git
cd article-to-knowledge-cards
npm run serve        # 打开 http://127.0.0.1:5178
```

不需要 `npm install` —— 前端零依赖运行。只有要打包 exe 时才需要装依赖。

也可以直接用在线版（GitHub Pages，零构建）：<https://qianwinner.github.io/article-to-knowledge-cards/>

## 5. 使用方法

安装后无需特殊语法，直接说明需求即可。

**粘贴正文**

```
把下面这篇文章做成知识卡片：

<粘贴正文>
```

**指定本地文件**

```
用 make-knowledge-cards 处理 ./docs/notes.md
```

**指定语言与偏好**

```
readings/2024-cache.md 这篇，帮我拆成卡片，自测题用中文
```

**触发词**：知识卡片、知识卡、读书卡片、卡片化、做成卡片、make cards、knowledge cards、flashcards。

Skill 会自动读取文件、判断原文是否够格、筛选候选、去重、按原文顺序输出，并在 footer 说明卡片数、来源与未收录内容。

## 6. 输入输出示例

### 输入

一个信息量很小的值班速记 `notes.txt`：

```text
快速记录，三件事。

1. 服务器今天重启了两次，都是内存打满自动触发的 OOM Killer。
2. 值班的时候记得确认监控告警通道是否正常，上周那次是告警短信发不出去，我们才知道磁盘满了。
3. 下周把日志清理脚本加上自动删除 30 天前的文件。

另外客户又问了一次那个接口超时的事，我先记在这里，还没定方案。
```

### 输出

原文只有两条可被反驳的断言，因此只出 2 张卡，第 3 条待办和末尾的未决问题不制卡：

```markdown
### 卡片 1 / Card 1. 服务器当天两次重启均由 OOM Killer 触发

**核心知识 / Core knowledge**
服务器"今天"重启了两次，两次都是内存打满后自动触发的 OOM Killer。

**简明解释 / Plain explanation**
原文未定义 OOM Killer，只说明它在"内存打满"时会被自动触发；本卡只用它在原文中的具体表现。原文给出的因果链只有一条：内存被打满 → OOM Killer 自动触发 → 服务器重启，两次重启共用这条链条。原文未给出具体数值——既没有记录内存占用量，也没有说明是什么负载把内存打满。

**自测题 / Self-test**
问：原文记录的这台服务器当天重启了几次？触发原因是什么？
答案：两次，都是内存打满后自动触发的 OOM Killer。

### 卡片 2 / Card 2. 上周磁盘写满未被及时发现，直接原因是告警短信发不出去

**核心知识 / Core knowledge**
上周磁盘已经写满，但值班人员没有通过告警得知——原因是告警短信发不出去，问题是在事后才暴露的。原文据此要求值班时确认监控告警通道是否正常。

**简明解释 / Plain explanation**
这里出问题的是把告警送到人手里的那条通路，而不是磁盘监控本身：磁盘写满这个信号已经产生，通道却断了，信号没有送达，于是发现时间被推到了故障发生之后。原文给出的对应动作是值班时先确认监控告警通道是否正常。原文未定义"监控告警通道"包含哪些通道，只提到告警短信这一种。

**自测题 / Self-test**
问：上周磁盘写满为什么没有被及时发现？
答案：告警短信发不出去，监控告警通道未确认正常，问题是在事后才暴露的。

---
**卡片数 / Cards**: 2
**来源 / Source**: notes.txt
**未收录 / Omitted**: 原文偏薄，卡片数由内容决定而非凑数——第 3 条"下周把日志清理脚本加上自动删除 30 天前的文件"是计划，末段接口超时"还没定方案"是未决问题，二者都没有可被反驳的断言，故未做成卡片。
```

注意几个细节：

- **没有凑到 5 张**。原文只有两个断言，就只出两张卡
- **待办没有变成卡片**。「下周加自动删除」没有断言，不满足「可被反驳」
- **术语没有越界**。OOM Killer 的机制原文没说，就标注「原文未定义」，而不是补一段教科书解释
- **没有「来源声明」行**。原文没有免责声明，这一行会被整行省略，而不是填「无」
- **footer 说明了为什么只有 2 张**。省略理由和数量决策一起交代

### 前端界面

仓库附带一个本地 GUI，把文章转成知识卡片。文章只在本机处理，不联网。

**技术栈**：原生 HTML + CSS + JavaScript（零前端框架、零构建步骤）+ Tauri 2 壳

选原生 JS 而非 React，是因为这个界面只做四件事——文本输入、卡片渲染、卡片库管理、复习调度，引入 Vite + React 会多出几百个 `node_modules` 和一层构建复杂度，对这个规模是纯负担。

### 视觉与动效（液态玻璃）

界面采用半透明毛玻璃语言，但**玻璃服务于层次，不抢焦点**。具体约束写在 `styles.css` 顶部，三条都不能破：

| 约束 | 原因 |
|---|---|
| 动效只用 `transform` / `opacity` | 动 `width`、`height`、`top` 会触发布局重排，卡片一多就掉帧 |
| `backdrop-filter` 只给大面积、少数量表面 | 顶栏、面板底、工具条、toast。卡片一律用半透明底色 + 描边模拟玻璃——几十张卡片各挂一层实时模糊，移动端会掉到 30fps 以下 |
| 文字与玻璃底的对比度必须 ≥ 4.5:1 | 玻璃是半透明的，底色随背后的环境光斑变化 |

玻璃质感由四层叠出来：

1. **环境光斑**（`body::before` 四个 radial-gradient）——不是装饰，是玻璃的折射对象。没有背后明暗变化，模糊和高光就没有意义。
2. **高光描边**（`inset 0 1px 0 0`）——玻璃「有厚度」的来源。只给边框和阴影，玻璃会像半透明塑料片。
3. **高光扫过**（`.btn::after` / `.card::after`）——悬停时一道光带斜掠过，用 `translate3d` 位移，不触发布局重排。
4. **极细颗粒**（`body::after`，SVG 噪声）——消除大面积渐变在 8bit 屏上的色带。

动效清单：面板切换淡入上浮、卡片入场错峰（`min(var(--i), 11)` 卡住上限，否则 100 张卡最后一张要等 3 秒）、卡片悬停抬升 2px、按钮按压缩放、Tab 选中亮条横向展开、复习翻面 3D 翻转、toast 弹性进场、错误提示轻微抖动、到期徽标呼吸。

**降级路径**（都是真的降级，不是摆设）：

| 环境 | 行为 |
|---|---|
| `prefers-reduced-motion: reduce` | 全部动画与过渡退回静态终态，高光扫过直接 `display:none` |
| `prefers-reduced-transparency: reduce` | 关掉模糊与半透明，环境光斑一并隐藏 |
| `prefers-contrast: more` | 描边加粗到 2px，弱文本提亮到 0.92 |
| 不支持 `backdrop-filter` | 退回不透明表面——宁可失去质感，也不能失去层次 |
| 移动端 | 模糊半径从 30px 降到 16px；≤640px 单栏 + 44px 触摸目标 + 刘海屏安全区 |

深浅色跟随系统（`prefers-color-scheme`）。Tauri 窗口主题固定为深色，桌面应用里不会命中浅色那一支；在线 Demo 则会跟随访客系统。

**界面结构**：三个 Tab。**生成**是左右双栏（左侧原文、右侧卡片）；**卡片库**与**复习**是整宽面板。

**核心交互**：

| 操作 | 说明 |
|---|---|
| 粘贴文本 | 直接在输入框粘贴，支持 Markdown / TXT |
| 选择文件 | 点「选择文件」载入 `.md` / `.markdown` / `.txt`，非支持格式会明确拒绝 |
| 生成卡片 | 点「生成卡片」或按 `Ctrl+Enter` |
| 复制提示词 | 把 SKILL.md 的硬约束压成一段提示词连同来源一起复制到剪贴板，交给模型补语义解释 |
| 存入卡片库 | 一键把这批卡片连同原文存到本机，之后可编辑、打标签、导出、复习 |
| 复制 / 下载 | 导出为标准 Markdown，含 footer 统计与原文声明 |
| 超过 60 张 | 自动按原文小节分批，编号跨批连续 |
| 复习 | 到期卡片按队列出现，先想再翻面，1/2/3 键对应三档自评 |

**规则引擎**：前端的 `card-engine.js` 实现了 SKILL.md 的硬约束——资格判定（待办、计划、预测、未决问题不做卡）、单卡单知识点、重复合并、可溯源（卡片内容必须能逐字回溯原文）、不凑数（原文支持几张就出几张）。

引擎对「解释」与「口径提示」的处理规则值得单独说明，因为这两项最容易变成填充：

| 字段 | 取源顺序 | 引不到时 |
|---|---|---|
| 简明解释 | ① 候选内部的因果子句 → ② 原文相邻句（带机制标志，或同段里本身不成卡的承接句） | 写明「原文未提供」，卡片上打橙色徽章，并在footer 记账。**绝不用固定模板句填充** |
| 口径提示 | ① 原文自带的免责声明（逐字）→ ② 相邻句里的口径限定 → ③ 紧邻的转折句 | 整行省略，不写「无」 |

规则引擎只搬运**有原文证据**的内容。语义级的矛盾（同一指标两个互斥数值、却没有任何标志词）规则引擎不判定，也不猜——那一层交给 Skill 或模型。界面上「复制提示词」就是这条分工的出口：引擎负责结构化与硬约束，模型负责语义。

**质量报告**：生成区顶部那块可展开的面板，把引擎的判定过程摊开——每个候选为什么被拒（按「计划 / 未决问题 / 预测 / 框架句 / 无内容信号 / 过短」分类）、哪些卡片的解释是原文没写的、哪些重复论述被合并进了哪张卡。「不凑数」是本项目的立身之本，只给一个数字等于让人没法验证。

**卡片库与复习**：

- 卡片库支持逐字段编辑。改了简明解释之后，「原文未提供」标记会自动解除并标为「人工补充」——引擎的诚实标注可以被人工补齐。
- 复习采用 SM-2 变体：`Again` 回退到 10 分钟后并下调 ease，`Hard` 间隔 ×1.2（下限 1 天），`Good` 按 1 天 → 6 天 → ×ease 递增；ease 恒被夹在 [1.3, 3.0]；连续 3 次 Good 且间隔 ≥ 30 天标记为已掌握。
- 复习界面刻意做成「先想 → 再翻面 → 再自评」三步。直接摊开答案会让复习退化成重读。

### 构建踩坑：必须带 `RUSTFLAGS="--cfg has_std"`

构建 Rust 侧时若报 `error[E0107]: struct takes 3 generic arguments but 2 generic arguments were supplied`，原因如下：

`indexmap` 的结构体定义分两个 cfg 分支：

```rust
#[cfg(has_std)]      pub struct IndexMap<K, V, S = RandomState> {}  ✅ 有默认参数
#[cfg(not(has_std))] pub struct IndexMap<K, V, S> {}                 ❌ 无默认参数
```

`has_std` 并非 rustc 内置标记，而是 indexmap 的 `build.rs` 用 autocfg 探测目标三元组是否含 std crate 后自行 emit 的：

```rust
autocfg::new().emit_sysroot_crate("std")
```

Rust 1.99 上该探测失败 → `has_std` 未定义 → 一律走 `not(has_std)` 分支 → `schemars` 写的 `IndexMap<K, V>`（依赖默认参数）编译失败。

**解决**：手动注入该cfg，让 indexmap 走对分支。

```bash
RUSTFLAGS="--cfg has_std" cargo build --release
```

`scripts/build-exe.sh` 已内置此 flag，无需手动处理。

**为什么不能靠降级依赖解决**：引入 indexmap 的开关是 `schemars` 的 `preserve_order` feature，而 `tauri-build` 硬性启用它；`schemars` 0.8.21 与 0.8.22 都声明 `indexmap = "^1.2"`（无上限），降版 schemars 无效；回退 indexmap 至 1.8.0 / 1.7.1 同样无效（这两个版本的 `not(has_std)` 分支也没有默认参数）。

**版本锁的必要性**：三个 tauri 包的依赖区间互相冲突，必须严格锁：

| 包 | 版本 | 原因 |
|---|---|---|
| `tauri` | `=2.12.1` | 要求 `tauri-utils ~2.10.1` |
| `tauri-build` | `=2.7.1` | 要求 `tauri-utils ~2.10.1` |
| `tauri-utils` | `=2.10.1` | 无 2.8.2 版本（build 侧最高 2.7.1） |

放开任一个版本会导致 `tauri` 与 `tauri-utils` 的 API 不匹配（报 `E0061`：函数参数数量不符）。

待 `indexmap` / `schemars` 官方适配 Rust 1.99 后，可移除 `RUSTFLAGS` 与版本锁。

## 9. 设计约束

构成这个 Skill 底线的硬规则：

- **可追溯**：任何数字、日期、名称、因果主张，都要能指回原文的具体行
- **不引入外部知识**：不补充教科书定义、真实统计数字、原文未提的名字
- **例子只能来自原文**，或基于原文数字的显式算式，且算式必须展示
- **不虚构权威**：不把主张安到原文没引用的人或机构头上
- **不改分类凑数**：把待办包装成卡片不增加假事实，但会虚增数量，禁止
- **不为凑数拆分**：一个知识点就是一张卡。上限提高后尤其要防把完整知识点切成多张
- **术语不越界**：原文没定义的术语只能用原文自身用法解释，解释不了就标注
- **保留声明与矛盾**：虚构声明、口径冲突、原文互斥说法都要留在输出里
- **保留来源自己的时间表述**（「上周」「今天」），除非原文给了具体日期

### 规则引擎测试

`npm test` 跑 **61 项断言**，覆盖：

- **13 项硬约束** × 4 类样本：卡片数上限、编号连续、无多句熔合、内容可溯源（核心知识/标题/口径提示/被引用的解释）、字段齐全、例子与自测二选一、计划类内容既不成卡也不混入其他卡、无占位符残留、标题与正文同源、解释字段不是模板句、解释来源标注正确、解释不是核心知识的复制、口径提示非空时必有原文依据
- **不凑数行为**：纯计划内容必须输出 0 张；极简样本不超过 3 张
- **原文声明保留**：三份带声明的样本，声明必须被识别并落到带数字卡片的口径提示
- **文本拼接**：英文句号后不粘连，中文换行处不插入多余空格
- **边界处理**：空输入、纯空白、超长输入（400 段）

测试过程中发现并修复了 8 个真实缺陷：

| 缺陷 | 症状 | 根因 |
|---|---|---|
| 去重过激 | 9 条候选被合并成 1 张 | 中文按单字算 Jaccard 相似度失真，阈值过低 |
| 溯源断裂 | 卡片内容无法逐字回溯原文 | 清理 Markdown 时删除了 `**`，改变了字符序列 |
| 多句熔合 | 单卡含 6 句 | 段落切分只按空行，未按句号上限切 |
| 长输入退化 | 400 段输入只出 1 张 | 上述去重缺陷的连带影响 |
| 解释注水 | 所有卡片的解释是同一句模板 | 无因果连接词时走 `else` 分支填固定文案 |
| 标题错位 | 标题讲成本压力，正文讲耐用性投诉 | `core` 是跨候选拼接的结果，标题取了上一段残句 |
| 口径提示空转 | 前端有渲染与导出分支，引擎从不赋值 | 引擎缺声明/口径/转折三类证据的搬运逻辑 |
| 计划句混入 | 卡片正文里出现「下周把日志清理脚本…」 | 计划句未被当作切分硬边界，只在候选开头做过一次判定 |

后四项是 v0.1.4 的修复，同时把断言从 38 项扩到 61 项——旧断言全绿并不代表输出正确，「解释是模板句」这件事没有任何一条断言能拦住。

## 11. 已知边界

规则引擎做的是结构化抽取与规则筛选，它的能力有明确上限，以下三类需要交给模型而不是继续给引擎加正则：

| 情况 | 引擎现状 |
|---|---|
| 原文没有解释句 | 标注「原文未提供」并打徽章，不编造。语义解释靠「复制提示词」交给模型，或在卡片库里人工补齐 |
| 语义级矛盾 | 同一指标两个互斥数值且无任何标志词时，引擎不标口径提示（宁可少标，不凭空造冲突） |
| 代码块落位 | 引擎把代码块从候选中跳过，SKILL.md 规定的「代码进Example、报错进核心知识」由模型执行 |

界面与流程上仍有三处已知不足：

| 情况 | 现状 |
|---|---|
| 浏览器端未做渲染回归测试 | 本机无可用无头浏览器，`check:ui` 只做静态契约检查。真实渲染与交互需人工过一遍 |
| 复习算法未按个人数据标定 | 现在是固定参数的 SM-2 变体。卡片过百、有真实「记得/忘了」记录后才值得换成 FSRS 并标定权重 |
| UI 语言仍只有中文 | 英文版 README 已就绪，界面本身还没有 i18n |

数据侧的三条边界，README 里也写明了：卡片与原文都存在浏览器 `localStorage` 里（**换浏览器、清理站点数据、无痕窗口关闭都会丢**，重要卡片请用「导出 JSON」备份）；`localStorage` 不可用时应用会降级为内存模式并在页脚明确提示，不会静默丢数据；Tauri 版用的是同一个 WebView 存储，与浏览器版数据不互通，需要用 JSON 备份搬运。
